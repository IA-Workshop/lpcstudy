## Method

- **Auditor:** `reviewer`, model `claude-opus-5-5`, fresh context, 2026-10-10, worktree `wu/0013-def0007-audit` at `0da91a7`.
- **Rules applied:** VV.7 (LVL0-constitution.md:148), LPC.PC.21a–b (project-constitution.md:163–170), `.claude/rules/tests.md`, DEVELOPMENT_WORKFLOW.md §4.7, and the classification rule in the WU-0013 plan (`reference` / `regression guard` / `defective`).
- **Scope:** the 14 tests in `tests/unit/test_{allocation,analysis,dynamics,embedding,ensemble,oracle,statistics}.py` and the helper `tests/unit/unit_helpers.py`. `test_conftest_markers.py` and `test_tools_test_impact.py` are out of scope.
- **Per test, four checks:**
  1. **Assertion.** What does the test assert?
  2. **Reference.** What value is it compared against? Was that value produced by the test itself (a literal, a hand derivation, brute force on raw data, or a known generating law), or by `lpcstudy` code?
  3. **Independence.** I read every `lpcstudy` function the test calls (file:line given in the table) and looked for a shared formula, a shared helper or a shared index expression between the code under test and its reference.
  4. **Numeric literals.** I listed each one (tolerances, thresholds, sample sizes and seeds) and checked it for a justification in the docstring or comments. Where none exists, I computed the sampling or round-off error myself to judge whether the literal is sound.
- **Error figures.** All Monte Carlo errors quoted below are my own calculations: delta method, linearized least squares, Greenwood approximation, or sqrt(2/n) for a sample variance. I ran them as plain NumPy arithmetic in a scratch file, outside both worktrees, with no `lpcstudy` import. I used the main checkout's `.venv` interpreter read-only.
- **No tests were run.** No test, `lpcstudy/` file or other section was changed.
- **Line references.** Unless prefixed, line numbers refer to the test file named in the row. Code references are `lpcstudy/<module>.py:<line>`.
- **Global finding.** None of the 14 docstrings states both a reference and a tolerance justification, as `.claude/rules/tests.md` (first bullet) and LPC.PC.21b require. So every test needs a docstring fix in WU-0013.2. The table separates whether a test has an independent reference from whether its docstring documents that reference.

## Tests found self-referential or without a justified tolerance (for WU-0013.2)

**WU-0013.2 should apply these fixes:**

- **Docstrings for all 14 tests.** A docstring must name the reference and justify the tolerance (`.claude/rules/tests.md`). No docstring does both today.
- **No loosened tolerance.** No fix below loosens a tolerance.
- **Tightened tolerances.** Where I propose a tighter tolerance, the developer must fix it in the docstring **before** running the test (LPC.PC.21b). If the test then fails, that is a finding about the code or the error analysis, not a reason to revert (PRIME.2).
- **Optional choice.** Keeping a current tolerance with the documented justification is always an acceptable alternative to tightening it.

**Self-referential (defective):**

1. **#4 `test_dynamics.py::test_observability_matches_independent_jacobians`.** The reference reuses the code's ν formula verbatim (L32 against dynamics.py:220–222). It also takes A from `delay_map_forward`, whose delay-index expression (dynamics.py:255) is the same as the code's (dynamics.py:219). Fixes, without touching L34's `rel=1e-8`:
   - (a) **Add a manufactured-solution test.** Use a linear step `s -> M @ s` (a JAX lambda) with M well conditioned, for example a rotation about a generic, non-axis-aligned axis times diag(1.1, 0.9, 1.0). The axis must be chosen so that (e_obs, M) is observable and AᵀA is invertible. Then A has closed-form rows e_obsᵀ M^{(D−1−k)τ}/σ_x and Q = M^{(D−1)τ}, and cond(Q) is small. Form J_G = A Q⁻¹ explicitly and compute ν_ref = ‖W J_G⁺‖_F with `np.linalg.pinv`, which is an SVD. This route differs from the code's normal-equations route, since tr(W(J_GᵀJ_G)⁻¹Wᵀ) = ‖W J_G⁺‖_F². State the tolerance from cond(J_G)²·2.2e-16.
   - (b) **Add an index-convention test.** `delay_map_forward(s_old)` must equal `delay_vectors` applied to the normalized `simulate_trajectory` path from `s_old`. That ties the row selection to the independently tested ordering (#5).

Before that, state cond(AᵀA) at the three states in its docstring. If cond(AᵀA)·2.2e-16 exceeds 1e-8, record that the current agreement is due to identical operation order and is not accuracy.

## Notes

- **The helper is independent but leaves a gap.** `unit_helpers._moments_from_draws` (unit_helpers.py:10–14) computes plain sample moments on the test side. It does not call `lpcstudy.ensemble`, so it is a valid independent route for #1, #8 and #9. Because of that, none of the 14 tests covers the production moment accumulation in `lpcstudy/ensemble.py`. This is outside DEF-0007 and is for successors.
- **Randomness.** All stochastic tests use `np.random.default_rng(<int>)`, which DEVELOPMENT_WORKFLOW.md §4.7 permits. No test uses unseeded randomness.
- **Silent-handling observations in the code under test.** These are outside this audit and are not test findings; they are for the main session to triage against LPC.PC.21d and DEF-0001:
  - `_per_state_spearman` returns 0 for an undefined correlation (analysis.py:405). The states that get 0 enter the mean at analysis.py:434–454, and no count is reported.
  - `autocorrelation_time` returns `max_lag` as a censored value (embedding.py:118–119), and the caller is not told that it was censored.
  - `oracle_weight` guards the curvature with 1e-300 (oracle.py:131).
- **Owner checkpoint for WU-0013.2.** The plan records no owner checkpoint. But if WU-0013.2 adds the independent log-rank reference (#12) and it exposes a discrepancy, the fix lands in `lpcstudy/statistics.py`. That is statistics code, so it needs owner review before the freeze (LPC.PC.11). The fixes listed above edit tests only.
- **Classification boundaries.**
  - #4 is `defective` under the plan's "copy of the same formula" rule, although it does verify the tangent bookkeeping independently.
  - #6 and #12 are `reference` because neither compares against the code's own output. #6's reference is uncited, so it does not yet meet LPC.PC.21a's requirement that a published value be cited in the code. If the citation cannot be verified, #6(a) becomes a `regression guard`.
