### Major

**M1. "Every differing leaf ... is reported" (pre-registration §5; plan `2026-10-27-phase-j-confirmatory-plan.md` line 78, WU-0058 acceptance criterion; ledger seq 54 "every differing leaf reported") is not met by the stored records.**

The files list the integer leaves (3, 2, 0, 4, 6) and, for the float classes, only the group count and the maximum (for example CONF-5: "class (a): 118 leaves, max metric 0.0039 at ...", "class (g): 294 leaves"). The dump arrays, by contrast, are listed one by one in `phasej-regen-compare.txt`, as §5 asks.
- The report §3 does not claim that every leaf is listed, so it is not false; but it does not say that this part of §5 was not delivered, and the WU-0058 criterion reads as met.
- Fix: write `compare_runs.py --all` output for the five pairs into the records (owner, into `runs/confirmatory/phasej-CONF-n-regen-compare-all.txt`, or main session into `docs/agent/records/` since the outputs are released), add their sha256 to report §8, and point §3 at them; or have the owner rule that the group summaries satisfy §5 and say so in §3. Either is a documentation act; no verdict moves.

### Minor

**m1. The "largest class (a) change (relative)" column uses `compare_runs`' class (a) metric, not a relative change of the named bound.** The metric is `|d| / max(|lo|, |hi|)` of the reference interval (`tools/compare_runs.py` ~line 1660). On CONF-5 the named leaf `.../shapley/O/ci/[1]` moved 0.000310 → 0.000396, a 28% change of the bound, but the metric is 0.0039 because the lower bound −0.0220 sets the scale; CONF-9 `chua/H2d/ci/[1]` moved 0.83% as a bound, metric 6.3e-4. The CONF-6 (0.219) and CONF-8 (0.129) parentheticals coincide with the plain relative change only because the moved bound was the larger one. Fix: name the metric in the column header or a footnote, and in the CONF-9 bullet replace "by at most 6.3e-4 relative on a quantity of interest" with "by at most 6.3e-4 of the interval scale (compare_runs class (a) metric)".
