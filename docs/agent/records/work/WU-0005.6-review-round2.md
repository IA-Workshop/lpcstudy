## (b) 2a39cf7: correct, no rule weakened, tested

**Part A line.** `report["probe_given"]` is set before the probe can be nulled. The new render expression parses as `A if not given else (B if not problems else C)`, because the conditional expression is right-associative. So:
- no probe gives "none given, r_A unknown";
- a given and accepted probe gives "accepted";
- a given and rejected probe gives "NOT USED".

This changes text only. Without a probe, `tail` was already `None`: `classify` adds "no Part A tail ratio", and no part can be N. So the old "accepted" line was a misleading label on a fail-safe result, and the fix removes a false statement.

**Coverage gaps.** A root now counts as present only when a leaf path is strictly longer than the root, that is, when the block has content. An empty `{}` flattens to a single path equal to the root.
- Effect on C0 itself: none. Violations are computed by `_c0_report` over the differing leaves, which this change does not touch, and an empty block has no leaf C0 could protect.
- A root with content but a sub-block that is empty still counts as present, so that case is, if anything, stricter.
- The round-1 hand-tree test (`:1238-1262`) still requires gaps for a non-empty `robustness` block, so a gap with content is still reported.
- The new test (`:1363-1380`) fails on the old code: the empty `systems`, `robustness` and `handling/robustness` roots would have produced gaps.
- The pilot-file coverage check of fix round 2 is unaffected, because those blocks had content.

**Unchanged:** rule R (`classify`, `tail_ratio`), P0, P1, `pairing_problems` and `probe_problems`.
