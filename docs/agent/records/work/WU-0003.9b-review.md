## Findings

**R1 (major, blocking): H1a `ratio` and `ratio_ci` keep the looser class rules, and the class mode also gives them back the whole-system scope.** `tools/compare_runs.py:793-797` (the `tolerance="class"` row), `tools/compare_runs.py:876-881` (`tolerance_chain`) and `tools/compare_runs.py:1068,1075` (`decide`).
- **Why it matters (a), the working default.** C4 defines the tag as the most-downstream dependence. It says a failure of correct code that follows "is reported and flagged, never loosened", and it retires the untagged default. By dependence these 18 leaves per pilot are cp, which the developer agrees with. The 1e-4 s rule they keep exists only because they were untagged, and C4 removes that reason. The plan already ruled on the identical case: for the sibling outputs of the same `curve_fit` (`fitted_inverse_dim`, `ci_inverse_dim`, `floor_rms`), the QoI rule is OF-7 and "**Not adopted**", with a working default of cp 1e-12 and a pointer. The note's "already fall under the 1e-4 s rule" describes the untagged default, not a ruling. Holding a cp leaf to the class rules is therefore an unadopted loosening chosen as the working default; the stricter reading should be the default until the owner rules (H4).
- **Why it matters (b), not in the developer's flag.** `tolerance_chain` returns `network`, so `in_scope(..., star=True)` lets a whole-system clip, nu-cap or replacement count license these leaves at 0.1 hw. Those counts concern the PLP, which the cp ratio does not depend on. This is the bypass that round 3 (R17) closed for every network-independent leaf.
  - Probe (test helpers, `with_h1a`, `ratio` 1.09 → 1.10 and `ratio_ci/[1]` 1.30 → 1.31, which is 77× the 1e-4 s tolerance): T1, T2 and T3 all **FAIL** with no count. With `CELL/counts/error_clips` +1, all **pass** under "discrete scope: 0.1 hw" (tol 0.017).
  - The H1a verdict ratio is the leaf where this matters most.
- **Fix.**
  - Make `tolerance="chain"` the working default for these two patterns (cp 1e-12).
  - Extend the `OF7_POINTER` condition (`compare_runs.py:1105-1108`) to `ratio` and `ratio_ci/[0|1]`.
  - Update the expected T2 count of the C6/OF-7 row (24 to 36 H1a leaves per pilot T2 pair).
  - Put the class mode to the owner as an extension of OF-7.
  - Separately, and whatever the owner rules, `star` in `decide` should follow the dependence chain (`chain_of(path)`), not `tolerance_chain(path)`, so that no cp-dependent leaf ever takes the whole-system scope.
  - Tests: change `test_the_h1a_ratio_is_cp_by_dependence_and_keeps_the_class_a_rule` to cp 1e-12 with the pointer, and add the R17 analogue for `ratio` and `ratio_ci` (a cell clip count does not license them).

**R2 (minor, owner ruling): `H1d/rows/nhat/spearman` is `network` in `compare_pilot`'s table but cp by the code.** `tools/compare_pilot.py:719-721`.
- **Why it matters.** The pair is `(ev.noise_sens[:, 0], m.noise_sens)` (`analysis.py:741`), with no estimator input. I confirm flag 3. The point estimate is held looser than its own interval (cp here), which is against C4's meaning of the tag. t2 rightly forbids moving it in this unit, and the override cannot reach it because the table decides first.
- **Fix (owner).** Rule the tightening. Then either:
  - re-tag the `nhat` member in `compare_pilot`, after checking the effect on its own v1 regression rule (`unchanged`, N1); or
  - give `compare_runs` an explicit, tested "tightening override" that may replace a table chain by a network-independent one, never the reverse.

**R3 (minor, information for the mathematician): some cp-tagged override leaves are not forward-stable direct arithmetic.** `tools/compare_runs.py:798-809`.
- **Why it matters.**
  - `H1d/rows/nhat/interval` is a percentile of resampled Spearman correlations, so it is rank-based and discontinuous in its inputs.
  - P2c `population/z_B` is a difference of two sums divided by an SE, so it cancels.
  - P2c `tightness/*` and `fraction_*` are taken over masked sets (`b_m > 0`, switching draws).
  - Under cp 1e-12, an ulp change in the cp chain on a T2/T3 pair could flip a rank or a mask and fail on correct code. That is C4-conformant (strict, flagged, never loosened). It also shows that the solver argument behind R1's class mode is not a carve-out that could be applied consistently.
- **Fix.** None in code. Ask the mathematician whether these leaves need a pre-registered expected-failure note like OF-7, so that a failure is read correctly at R1.

**R4 (low): an ambiguity on a non-float leaf would abort the report, and one docstring overstates the overlap guard.**
- **Why it matters.**
  - `tag_summary` (`compare_runs.py:1359-1361`) calls `chain_source` for every differing row, including integer, string and bool rows. Since `chain_source` now raises on two table matches, a non-float ambiguity, which needs no chain, would end the comparison with exit 2 and no rows.
  - This is latent: 0 such leaves on the 29 files. It is fail-closed, not silent.
  - The `_build_tags` docstring says "A pattern may not overlap another (the table raises)". `cp.Table` rejects only identical patterns; an overlap is caught at lookup (`tag_of`) and by the fixture test.
- **Fix.** Restrict `tag_summary` to rows of kind `float`, and correct the docstring.

**R5 (low): one new test assertion is weaker than the behaviour it pins.** `tests/unit/test_tools_compare_runs.py`, TD case of `test_an_untagged_float_leaf_is_not_computable_in_every_tier_even_when_equal`: `res.exit_code in (1, 2)`.
- **Why it matters.** The probe gives exactly 2, and the clean TD pair gives 0. Accepting 1 would let an unrelated TD failure mask a regression of the C4 branch.
- **Fix.** Assert `== 2`.
