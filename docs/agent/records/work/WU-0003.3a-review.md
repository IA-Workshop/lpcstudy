## Findings

**R1 (medium; developer). A dump that fails its reproduction check still supplies the point kappa_E.**
- **Where.** tools/rehearsal_report.py:657-668 and 772-780. `check_reproduction` records the MISMATCH but does not stop. `kappa_from_dump` then computes and returns kappa from the same dump. `project_row` uses it as `x_lo = x_hi`, the row is labelled "kappa_E … from the dump", and the summary counts it as a "point estimate from the dump".
- **Why it matters.** The tool's own contract (Log: "before it is used the dump's statistic … must reproduce the results leaf") and B1 item 6 make the reproduction the licence to use the dump. Exit 1 flags the run, but the printed projection for that criterion rests on arrays that are known not to be this run's.
- **Fix.**
  - After recording the defect, do not use the dump for that criterion. Raise a `NotComputable`, so the range is used and printed as FALLBACK (the exit stays 1), or mark the row and the summary explicitly as "dump MISMATCH: not used".
  - Add a test: a mismatching dump yields the range on that row and is excluded from the summary's point-estimate count.

**R2 (medium; applied-mathematician, not a developer fix). The V_s/V_d split assumes that a draw's weight is independent of that draw's forecast errors.**
- **Where.** Note §M3, implemented faithfully at tools/rehearsal_report.py:612-630 and 393-395.
- **What the pipeline does.** The weight of evaluation draw d (`core/weight_href/<rule>[:, d]`) is computed from that draw's own noisy observation: `deployable_profile(ev, …)` and the recurrence distance R, at dump.py:309 and 318-320. The realized error `w·cp_err + (1−w)·plp_err` uses the same draw's errors. So E[realized_i | state] ≠ mean_d V_i(w_d).
- **Effect on kappa.**
  - The residual (realized − draw-free) has a per-state mean that does not shrink as 1/E. The formula nevertheless scales it by E_run/E_full, which biases kappa down, so the projection is too narrow.
  - Conversely, V_i built from only E_run = 2 weights carries weight-draw noise into V_s, which biases kappa up.
  - The net direction and size are unknown.
- **Why the tests cannot see it.** The f2 and unit synthetic worlds draw independent noise.
- **Why it matters.** It feeds the H2c, H2d and H3c projections behind the owner's sample-size decision (WU-0003.6).
- **Ask.** The mathematician should confirm that the bias is negligible, or define a check. For example, a per-draw squared-error array in the dump would separate the per-state mean of the residual from the 1/E part. A dump addition would be a new sub-task.

**R3 (low; developer, documentation of a statistical test). The f2 Monte Carlo statement and the Log's bias attribution are inaccurate.**
- **Where.**
  - tests/slow/test_rehearsal_report_mc.py:15-19 and 25-26: "bias of kappa-hat is below 1e-3, under the 4 SE bound" (4 SE is 7.6e-4 for diff, s_d 2), and "probability that a correct, unbiased estimator breaks the bound is 6e-5 per case".
  - WU-0003-dev-rehearsal.md:544: "+7e-4 (0.1% of kappa) … the second-order term estimated in the docstring". The docstring estimates no second-order term.
- **Why it matters.** The test discipline requires the Monte Carlo error to be stated in the docstring (test-discipline.md, statistical tests). The stated false-failure rate is off by about 500×.
- **Fix.** Text only, with no change to the bound, seed or R:
  - state the second-order bias, about +3.6e-4 analytic and +3.9e-4 ± 0.4e-4 simulated at t = V_d/V_s = 4, which is 2.1 SE at R = 2000;
  - state the resulting per-case false-failure probability, about 3% (diff, s_d 2) and about 1% (ratio, s_d 2);
  - correct the Log: the bias is about +3.9e-4 (0.05% of kappa), and the rest of the +3.85 SE is seed noise.

  Whether f2 should compare with truth plus the predicted bias is for the planner. It must not be changed to pass.

**R4 (low; developer, PRIME.4). Silent default for the block length.**
- **Where.** tools/rehearsal_report.py:775: `int(cfg.get("bootstrap_block", BLOCK))`. A missing config leaf silently becomes 5.
- **Fix.** Use `dig(cfg, "bootstrap_block")`, so that a missing leaf is "not computable" and is counted.
