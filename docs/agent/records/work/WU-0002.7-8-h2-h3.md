**M1, H3b construction: correct as planned.**
- The resampling unit is the construction state with all its E draws: `rows = (idx[:,None]*E + arange(E)).ravel()`. This matches C3.
- The indices are the `block_bootstrap` indices (blocks of 5, starts in [0, n−5]). Both trees are refit in every resample, the curvature weights are those of the resampled rows, and the point estimate is the full-data fit.
- The interval conditions on the fitted proxies, since the deployable profile is not refit. That is acceptable, but the docstring must state it.
- **Interval method: percentile, not basic.** Importances lie in [0, 1] and D lies in [−1, 1]. The weight importance under the hypothesis sits at the boundary 0.
  - The basic interval [2θ̂ − q_hi, 2θ̂ − q_lo] is anti-conservative there. In my per-draw-x C1 variant, θ̂ = 0.051 with q = [0, 0.119] gives a basic interval of [−0.017, 0.102], against a percentile interval of [0, 0.119]. The basic interval's upper bound is lower, so it favors a pass.
  - Percentile intervals respect the range and are transformation-invariant.
  - Coverage is not guaranteed for these non-smooth functionals: the split variable can switch, and the bootstrap is inconsistent at boundaries. This is why stability is reported.
- **Non-smoothness of max is conservative for D > 0.** When two of the *other* coordinates tie, E[max] ≥ max E, so D̂ and its bootstrap are biased downward. When Λ̃ ties with one other coordinate, D is locally a smooth difference.

**M2, D and stability: correct.**
- Compute D_r from the joint importance vector of resample r: D_r = imp_t,r(Λ̃) − max_{j≠Λ̃} imp_t,r(j). Never take the difference of separate quantiles.
- Stability = #{r : D_r > 0 strictly}/B. The denominator B includes NaN resamples, which count as "not > 0". D = 0 counts as "not first".
- **Exact equivalence.** At B = 2000 the lower bound sits at position h = 1999·0.025 = 49.975 in the sorted values. So lo > 0 iff k = #{D_r ≤ 0 or NaN} ≤ 49, or k = 50 with a positive interpolation. The D criterion is therefore "stability ≳ 0.975", and the two reported numbers carry nearly the same information.
- The Monte Carlo SE of stability is √(s(1−s)/B), at most 0.011, and 0.0035 at s = 0.975.

**M3, degenerate fits: NaN at the unfavourable tail, agreed.**
- On a single-leaf tree, sklearn silently returns all-zero importances (checked: constant target, `n_leaves == 1`). The normalization is 0/0, so NaN is the mathematically correct value, and keeping 0 would favour the weight part.
- Detect it with `tree_.n_leaves == 1`, never by testing for an all-zero vector.
- A degenerate weight tree makes imp_w NaN, which goes to +inf. A degenerate horizon tree makes D_r NaN, which goes to −inf and counts against stability.
- Count `degenerate_fits` per tree. A degenerate full-data fit means "not computable", so the result is inconclusive (A3).
- **Add test C4:** a constant w\* gives a degenerate point fit, so the result is inconclusive and `degenerate_fits` counts it.

**M4, H2b levels: consistent with v3 §7.**
- H2b is primary, so (i) and (ii) both use 1 − 0.05/3. The curves and the ρ = 2% change are reported only, so they use 95% ("everything else uses 95%").
- (ii) is the bootstrap of the mean of per-state paired differences d_i = w\*_i(10⁴) − w\*_i(10³) at H_ref, with one index array, at ρ = 1%. Clip ties at w\* = 0 put an atom at d = 0, which is harmless for a mean.
- **Monte Carlo error of the endpoints at B = 2000** (√(a(1−a)/B)/φ(z), recomputed):
  - at 1 − 0.05/3: 0.0895 bootstrap SD, which is 3.7% of the half-width;
  - at 95%: 0.0597 bootstrap SD, which is 3.1% of the half-width.
- Both are under the 10% rule. At the projected half-width of 0.03, the endpoint Monte Carlo SD is about 0.001.

**M5, H2e.**
- **Two-pass Pearson within each chunk is right.** Chunks split states, not draws (`ensemble.py:367`), so all M draws of a state are present.
- **The "CP constant" test as exact equality, `np.ptp == 0`, is right.** CP's error is a deterministic float function of the retrieved indices (`ensemble.py:228-242`), so identical retrieval gives bitwise-identical errors.
- **The mask is required, not optional.** On a constant row with a non-dyadic value, two-pass gives 2.2e-17 rather than 0, and the moment formula gives 1.2e-10, which reproduces the pilot's ~6e-9 residue. Recommendation: make E1's constant row a non-dyadic constant such as 0.3712345, so that the override is exercised.
- **PLP-constant set to 0: adopt.** This answers O2, and it is equal or stricter.
  - In both cases, cov = 0 exactly, and 0 is the covariance-consistent value.
  - PLP's errors are common across library sizes: the oracle draws are keyed without n_lib (`pipeline.py:250`), and ψ is trained per ρ. So PLP-constant is a property of the state, and its change is exactly 0.
  - Setting it to 0 therefore pulls the median toward 0. That is stricter than dropping the state, and proportionate, where voiding H2e would not be.
  - Report the CP-constant, PLP-constant and both-constant counts separately, and the count of exact-zero differences.
  - A median with an atom at 0 can stick the lower bound at exactly 0, which is inconclusive under the strict rule. That is intended.
- **Per-state precision.** The sample-r bias is at most r(1−r²)/(2M), about 0.001, and the SE is about 0.07 per state. Both sit inside the state-level variance that the bootstrap captures.
- **E1 tolerance.** The observed maximum |two-pass − corrcoef| was 1.1e-15 over 1200 rows, with |mean|/sd from 0 to 1e5. 1e-12 is valid; **T: may tighten to 1e-13.**

**M6, H3a Holm family: correct, and conservative.**
- The family is all K_real − 1 consecutive pairs, with a missing or degenerate pair entering at p = 1 and its raw value reported as None. Since `pass` already requires every pair to be computed, p = 1 only raises the other pairs' reported Holm p.
- **C: tie order.** `np.argsort` with the default kind is not stable here (SIMD sort). On tied arrays with K ≤ 16, 19,534 of 30,000 orders differed from `kind="stable"`. KM medians are integer steps, and NaN maps to inf, so ties are realistic.

  - If the smoke has a tie, list it as changed.
- **O1, n ≥ 50 per regime.** The literal reading of A3 is stricter: it only turns pass into inconclusive. It is not needed for validity, since the log-rank χ² is adequate with about 10 events per group.

**M7, the unfavourable-tail rule.**
- **C: do not rely on `np.quantile` with ±inf.** It returns NaN for 0·inf and inf−inf: two +inf at B = 20 and p = 0.95 give NaN, and one +inf at B = 21 gives NaN where the right bound is finite.
- **Rule.** a = (1 − level)/2, and n_nan is the number of NaN resamples.
  - The lower bound is −inf iff n_nan ≥ ⌈aB⌉, with NaN placed at −inf.
  - The upper bound is +inf iff n_nan ≥ ⌈aB⌉, with NaN placed at +inf.
  - Otherwise the bound is `np.quantile` of the substituted array. That interpolates only finite order statistics, and it is bitwise equal to `block_bootstrap` when n_nan = 0.
  - ⌈aB⌉ coincides exactly with the order-statistic rule for every B in 10..3000 at levels 0.9, 0.95 and 1 − 0.05/3. The thresholds are 50 and 17 at B = 2000, and 5 and 2 at B = 200.
- **C/T: place NaN outward on both sides,** not only on the pass side.

  - For the band [0, 0.2), the pass side is high; for D, it is low.
- **C: S3 arithmetic.** At B = 20 and level 0.9, aB = 1, so "1 NaN (< α/2·B)" is wrong: 1 = aB, and the bound is infinite. Use B = 40 (aB = 2) with 0, 1 (finite), 2 (infinite) and all NaN.
