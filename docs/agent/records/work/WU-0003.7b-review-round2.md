- **Why it matters:**

  - **Effect on the pending runs: none.** The integration test asserts `extra_href_equal is True`. Without a NaN or a signed zero in the V4 `H_ref` errors, both readings give the same result. So R9 does not block the smokes.
- **Fix (before the unit closes):** one of the following.
  - (a) The planner amends D3 to the NaN-equal reading, with its reason: an identical NaN in both calls is not a defect of the second call. The developer then words the check as "value-equal (IEEE `==`), NaN equal to NaN" instead of "bitwise".

  - **Answer (developer, fix round 2):** fixed in 49f440d (option (b)). The comparison is strict and bitwise: bit patterns via `view(uint64)`, so +0.0 and -0.0 differ, and a NaN counts as unequal even when both calls carry it, which makes `v4/extra_href_diff` nonzero and logs the WARNING.
