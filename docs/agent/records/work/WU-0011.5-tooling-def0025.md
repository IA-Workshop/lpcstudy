### Scope

1. `tools/test_impact.py` gains two rules, and no others:
   - **Direct-import rule.** A test file (any tier) that imports a changed `lpcstudy/<m>.py` directly is selected, whatever its file name. "Imports directly" is the edge rules of `build_graph` applied to the test file's syntax tree (module-level or nested; `import lpcstudy.m`, `from lpcstudy.m import x`, `from lpcstudy import m`). Not transitive; not a string or comment mention; not `importlib.import_module` (a limit, written in the docstring).
   - **Scan-the-source rule.** A test file whose text contains `glob("*.py")` (which also matches `PACKAGE.glob("*.py")`) or the name `lpcstudy_graph.json` reads the package source or its hand-written graph; it is selected for any change to a `lpcstudy/*.py` file. This covers `test_identifiers.py`, `test_data.py` and `test_tools_test_impact.py` (the last also answers the DEF-0016 request that a change to any `lpcstudy/*.py` select the graph-fixture test). It does not fire for a change to a test, tool, doc or config file.
   - `test_validation.py` on a change to `analysis.py` follows from the direct-import rule (it imports `lpcstudy.analysis`); there is no special case.
   - Slow and gpu files reached by either rule are listed as `excluded` unless the flags are given, as for every other rule. Not selected beyond these rules: no new transitive depth, no new tiers, no change to the existing rules' output when no test imports the module directly and no scan test exists.
2. `tests/unit/test_identifiers.py::test_no_stale_identifier_in_the_package`: the stale-identifier regex becomes whole-token: `(?<![A-Za-z0-9])(?:H1e|H1f|H2f|H3d|T1)(?![A-Za-z0-9])|h1e_|h1f_`. The two prefix forms `h1e_` and `h1f_` stay as they are (no false positive was reported on them). The regex moves to a module constant (`STALE_ID`) so it can be tested. Then `lpcstudy/budget.py` `COVERAGE_PROVENANCE` gets the exact log name `slow-20261011T165447Z.log` back, without the sentence about the elided letter, and `tests/unit/test_budget.py` asserts it.
3. DEF-0025: `run_robustness` filters `d > spec.dim` (was `>=`). The dimensions the filter now or already dropped (`d < spec.dim`, `d == spec.dim`; the base dimension `d == embedding_dim` is the base cell, not a skip) are **counted** in `Study.skipped_variants` (a dict system -> labels, like `failed_variants`) and **reported** by one `WARNING` per system from `run_robustness` and one aggregate `WARNING` from `run_handling`. Before this change a dropped dimension was silent. The results JSON and the `handling` schema are not changed (no new leaf, no report text), so no preset's results change; exposing the count in the JSON would need a schema bump and a report line, and is left as a follow-up for the owner.
