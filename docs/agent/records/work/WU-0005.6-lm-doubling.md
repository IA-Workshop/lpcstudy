**Decision rule (fixed now; NVVUQ.9, the tenth rule, strict as M9).** It applies per QoI part and system, at pilot.
- **D1, negligible:** d₁ < 0.05, no verdict changes, and the 30-iteration reference is credible. Credible means that Part A at pilot shows median ‖ŝ₃₀ − ŝ₆₀‖ ≤ ½ median ‖ŝ₁₅ − ŝ₃₀‖ over moving estimates, and the 30 → 60 fraction is ≤ ½ the 15 → 30 fraction.
  - Then the error at 15 is ≤ d₁ + 2d₂ ≤ 2d₁ < 0.1·hw (geometric tail with ratio ≤ ½).
  - Size reported: d₁·hw, flag "yes".
- **D2, undetermined:** 0.05 ≤ d₁ < 0.1, or the credibility check fails. Then the pilot is run at 60, with size d₁ + 2d₂, negligible iff that is < 0.1 and d₂ ≤ d₁/2. If d₂ > d₁/2, the result is "not converged at 30": the size is reported as at least d₁ and the flag is "no".
- **D3, not negligible:** d₁ ≥ 0.1, or any verdict changes between 15 and 30. The size reported is d₁·hw (a lower estimate) and the flag is "no". This is a finding for the owner (O5).

### M1. Size measure, trigger and bound

- **d₁: correct.**
  - The 10% rule concerns the reported interval, and every verdict reads an endpoint. So the size of a numerical error on the QoI is the largest error of the point and of the two endpoints, each relative to hw. Signed r values reported beside d₁ = max|r| are right.
  - The size must use hw₁₅ (the design arm), as planned.
- **Bound d₁ + 2d₂: correct under a hypothesis.**
  - For each component x, |x₁₅ − x_∞| ≤ |Δ₁ₓ| + |Δ₂ₓ| + Σ_{j≥3}|Δⱼₓ|. If every later doubling at least halves the change (|Δⱼ₊₁| ≤ ½|Δⱼ| for j ≥ 2), the tail is at most |Δ₂ₓ|, so |e₁₅| ≤ d₁ + 2d₂.
  - **H-geo** is the hypothesis that the QoI-level ratio is at most ½ at every doubling after 60. Three levels cannot verify it; it must be named in the row text.
- **"Credible ⇒ error at 15 ≤ 2d₁": false as an implication.** The QoI aggregates thousands of LM runs. Most converge in a few iterations, but a slow subpopulation (zig-zag valleys, late basin hops) keeps moving. QoI functionals (medians, clipping of w* at 0 and 1, eligibility thresholds, membership) are not monotone in the per-estimate moves.
  - **Counterexample (E3, ρ = 0.01, start 0.02, median).** d(15→30) = 4.5·10⁻¹⁰, but d(30→60) = 0.0127, and the error at 15 against 240 iterations is 0.0127. A "2d₁" bound would be wrong by a factor of 3·10⁷.
  - On the same data, the per-estimate movement *contracts*: the total Σ‖Δŝ‖/(ρν) has ratios 0.44, then 0.31.
  - **The ratio test is not sufficient either (E3, ρ = 0.01, start 0.2, median).** The QoI ratios are 0.30 (passes ≤ ½), then 0.53, then 2.04. The bound d₁ + 2d₂ = 0.252 is below the true error 0.280. The per-estimate tail at 60 → 120 had ratio 0.62 (E3b), so the added tail condition r_A ≤ ½ (rule R) catches this case.
  - These are surrogate QoIs with heavier tails than the clipped study QoIs. They prove the logic, not the pilot's magnitudes.
- **The plan's median criterion is insensitive.** "Median over moving estimates" contracted by factors of 8·10⁻⁷ to 0.18 in every configuration (E1, E3b), while the fraction above 0.1ρν contracted only by 0.35 to 0.69. The median reflects the fast majority, while the QoI reacts to the slow tail. The fraction criterion is the binding one and should be kept as a diagnostic.
- **Lower estimate "≥ d₁".** |e₁₅| ≥ |x₁₅ − x₃₀| needs monotone convergence: e₃₀ has the sign of e₁₅ and |e₃₀| ≤ |e₁₅|. Name it in the text.

### M2. Endpoints or point only

- **Order statistics do not jump under common indices.** The k-th order statistic is 1-Lipschitz in the sup norm, and so is the linear quantile (a fixed convex combination of two order statistics). So |Δ endpoint| ≤ maxᵦ|T*ᵦ(30) − T*ᵦ(15)|. It held in all 60 E2 data sets.
  - The common-index premise holds for all five QoIs. Their bootstrap indices depend only on (n = all states, B, block, seed label): `bootstrap_values` in `h2a_initial_segments`, `h2a_part_ii`, the H2b noise block (`config.seed + 3`), `_paired_change` and `h3c_ratio`. Eligibility and the domain are re-evaluated inside each resample.
- **Endpoint changes have real Monte Carlo noise from finite B.** An endpoint moves with the change of the one or two resamples at the quantile rank, not with an average. Measured E2 values, as RMS of the change error against a B = 20000 (or 8000) reference, over hw:

  | Statistic | B | RMS of change error / hw | Endpoint MC SE / hw |
  | --- | --- | --- | --- |
  | mean-type, n = 300 | 500 | 0.020–0.022 | 0.087 |
  | mean-type, n = 300 | 2000 | 0.012 | 0.040 |
  | median with 3 eligibility flips, n = 500 | 500 | 0.039 (lo), 0.089 (hi) | 0.093 |
  | median with 3 eligibility flips, n = 500 | 2000 | about 0.037 | 0.051 |

  So at the pilot B = 500, the change noise of a median-type endpoint is at the level of the 0.05 trigger.
- **Recommendation: keep d₁ = max(|r_pt|, |r_lo|, |r_hi|).**
  - Noise inflates d₁ and d₂, so it pushes toward "not certified" or "not negligible", never toward a false "negligible" through S. The endpoints are what the verdicts read.
  - **Do not use `ci_mc_se` as a floor, for two reasons.**
    1. At B = 500 it is 6 to 9% of hw (WU-0008 M2; E2), so a floor would make the 0.05 trigger and the 10% flag vacuous. That is a loosening.
    2. It is the error of one endpoint, while the paired change error was 0.24 to 0.96 times it in E2.
  - **Report:** the arg-max component; r_pt, r_lo and r_hi; `ci_mc_se`/hw at both arms, as context.
  - **Label "endpoint-limited at B = …"** wherever the class of rule R computed with r_pt alone differs from the class computed with all three.

### M3. Per-estimate tolerance and SEs

- **ν convention verified.** V2 (`check_cramer_rao`) reads E‖W(ŝ_t − s_t)‖² ≈ ρ²ν², and `make_observability` gives ν = √tr(W Φ (AᵀA)⁻¹ Φᵀ Wᵀ). So ρν is the RMS Cramér–Rao error of ŝ_t in whitened units, and 0.1ρν is 10% of the per-estimate statistical error.
- **Why 0.1 is a sensible descriptor.** To first order, the PLP error at H_ref is a linear map of the ŝ error. A move of 0.1ρν therefore changes that estimate's squared error by at most about (2·0.1 + 0.01) of its expected value, and the amplification cancels in the ratio. It is a descriptor only, because the QoI decision comes from Part B.
- **Corrections:**
  - Use ν₃₀ as the denominator at **every** doubling (15→30, 30→60, 60→120), so that the ratios compare like with like.
  - Exclude estimates with `nu_replaced` or `state_replaced` at any level from the ratios, and report their counts (PRIME.4).
  - Keep the "> 0.1·‖ŝ₃₀ − s_true‖_w" fraction for comparison with WU-0005.4. It is noisier, because the realized error is χ₃-distributed.
- **Additional statistics (tail-sensitive):**
  - T = Σ‖Δŝ‖_w/(ρν₃₀) and F = the count above 0.1ρν₃₀, at each doubling;
  - the 0.99 quantile and the maximum of ‖Δŝ‖_w/(ρν₃₀);
  - for per-state PLP MSE at H_ref: the mean of |relative change| and its 0.9 and 0.99 quantiles beside the median (E1: the median per-estimate change is 0; with about 3% of estimates moving at a small start error and 16 draws per state, most states have no moving draw).
- **SEs.**
  - SD(pᵢ, ddof = 1)/√n_states is the cluster-robust SE for equal cluster sizes M with independent states.
  - Test states lie on one trajectory, and the study's dependence model is block 5. So also report the batch-means SE over consecutive blocks of 5 states, and use the larger. In E1 they agreed within 20% (for example 0.0093 against 0.0078).
- **What the SEs are for.** They serve transfer only (O4). On DEV-0 the iterative change is a deterministic number, so no decision reads an SE.

### M4. Part A as a stand-in for Part B at 60: no

1. **No theorem links the two (M1).** Per-estimate contraction does not imply QoI contraction (E3 counterexample).
2. **Coverage is incomplete.** Part A as planned (core cell, test split, oracle draws) feeds only H2a.
   - H2b(ii) at ρ = 0.01: its PLP estimates are bitwise those of core-cell test rows 0–299, because the network, unit noise and chunk shapes are the same.
   - H2b(i) reads ρ ∈ {0.005, 0.02, 0.05}, where LM starts and convergence differ (worst at 0.05).
   - H3c reads the fitted A4 and A5 (construction and calibration oracle moments) and the test **eval** draws.

**Decision:** run pilot Part B at 60 unconditionally. This is a tightening, and the skill requires three levels anyway. Part A stays as the diagnostic and supplies the tail condition r_A of rule R.

Part A should cover every PLP input of the five QoIs:
- the core cell, all three splits, oracle and eval draws;
- the noise-sweep cells' test rows 0 to n_test_sweep − 1 at every ρ ≠ ρ_core;

### M6. P0 and reproducibility of the probe

- **P0 as written cannot hold.**
  - `cell_handling` pools the oracle kind over `SPLITS` (construction, calibration, test), so the core cell's `by_kind.oracle` has (600 + 300 + 500)·200 estimates at pilot.
  - A test-only probe has 500·200, so `n_estimates` and every quantile differ by construction.
  - Per-split summaries are not stored.
- **Exact equality is attainable** under the conditions below. E1(a): the same chunking gives bitwise-identical results. Different batch shapes differ by up to 2.2·10⁻¹⁵ (chunks of 40 or 24 against 512) and 3.2·10⁻⁹ (batch 1). So **chunk shapes must match**.
  - **Chunking.** Splits in `SPLITS` order; oracle chunks of `6000 // M` rows (30 at pilot: 600 = 20·30, 300 = 10·30, 500 = 16·30 + 20); eval chunks of `6000 // n_eval_draws` rows; sweep cells with rows 0 to n_test_sweep − 1, chunked the same way.
  - **Environment.** Same commit, host, `LPC_THREADS` as the compared arm (8 at pilot; the probe must not default to another value), `XLA_FLAGS`, jax and jaxlib.
  - **Network and estimator.** The network is retrained in-process. Each level's estimator is built as `dataclasses.replace(setup.estimator, refine_steps=k, _fn=None)`.
- **Latent hazard (found here).** `StateEstimator._fn` is an init field (`field(default=None)`), and `dataclasses.replace` copies it (checked). If `setup.estimator` has been called once, for example by the K6 identity check, then `replace(setup.estimator, refine_steps=30)` silently runs the cached 15-iteration program. Then d₁ = 0, and the study would read "negligible". The pipeline itself never replaces an estimator, so production values are unaffected. A library hardening (`init=False`) is a separate item for the main session.
- **P0 (corrected), exact.**
  - For each arm k ∈ {15, 30, 60} that has a Part B run, the probe's pooled `lm_summary` over the three splits equals `handling.cells[<core id>].lm.by_kind.oracle` in every key (None = None).
  - Its sums of `lm_nonfinite_cost`, `lm_nonfinite_jacobian`, `invariant_mean_replacements` and `nu_replacements` equal `by_kind.oracle.counts`.
  - The same holds for `by_kind.eval` and for each covered sweep cell's `by_kind.oracle`.
  - A failure halts Part A (`/refer`).
- **Fallback, fixed now; usable only through a documented correction.** The cause must first be identified as compilation-level (not a defect) and the C0 item 2 leaves must be equal. Then the WU-0005.4 M7 tier (i) values apply:
  - residual summaries within 10⁻⁸ relative;
  - `fraction_no_decrease` exact;
  - `median_iterations` within ±1;
  - `fraction_above_chi2` within (number of estimates with c/ρ² within 10⁻⁸ relative of the threshold)/n.

### M8. χ² crossings

- **Report separately: yes.** Use the reference c/ρ² ~ χ²_{D−m} to first order, for the exact model in the right basin (WU-0005.4 M1). Take the threshold per cell from `gof_threshold(D − m)`: 18.4668 at D = 7; 13.8155 at D = 5 and 24.3219 at D = 10 (scipy, checked). Report:
  - the count above at 15, 30, 60 and 120;
  - the above→below transitions at each doubling;
  - the share of T and of F that they carry. In E1 crossings carried 11 to 59% of T(15→30).

  The estimates still above at the last level are the "wrong basin or not converged" group. Compare their count with the v3 §4 "about 2%" and with 0.001·n false alarms. Do not read it in misspecified variants.
- **They stay in the total.** A crossing is an estimate that more iterations take to a better fit, so it is iterative error of the 15-iteration estimator. It is not the kept wrong-basin share.
- **New exact check P1 (prefix property).** The scan of length 2k runs the length-k scan first, and the carried cost never increases. E1(b) confirmed this bitwise: u₁₅ = u₃₀ after 15 iterations, and c₆₀ ≤ c₃₀ ≤ c₁₅ for all 8192 estimates. Hence:
  - **Part A, per estimate:** c_{2k} ≤ c_k and accepted_{2k} ≥ accepted_k exactly, so there are 0 below→above transitions.
  - **Part B, every cell and kind with estimates:**
    - equal `n_estimates`;
    - `median_residual`, `p95_residual`, `fraction_above_chi2`, `nonfinite_residuals` and `fraction_no_decrease` non-increasing in k (None = +inf);
    - `median_iterations` non-decreasing.
  - Order statistics are monotone under elementwise order, so these are exact. A violation is a finding (a scan-length-dependent compilation or a broken knob), not a tolerance.

### Decision rule R (documented correction; replaces D1–D3)

Inputs per system and QoI part, at pilot:
- **Part B changes.** For x ∈ {pt, lo, hi}: Δ₁ₓ = (x₃₀ − x₁₅)/hw and Δ₂ₓ = (x₆₀ − x₃₀)/hw, with hw = (hi₁₅ − lo₁₅)/2. Then d₁ = maxₓ|Δ₁ₓ|, d₂ = maxₓ|Δ₂ₓ| and S = d₁ + 2d₂.
- **Part A tail.** r_A = max(F₆₀→₁₂₀/F₃₀→₆₀, T₆₀→₁₂₀/T₃₀→₆₀) over the Part A cells feeding the QoI. r_A = 0 if F₆₀→₁₂₀ = 0, and r_A = ∞ if F₃₀→₆₀ = 0 < F₆₀→₁₂₀.

The classes:
- **N, negligible (flag yes).** All of these hold:
  - the part verdict is the same at 15, 30 and 60;
  - d₂ ≤ d₁/2 (d₁ = d₂ = 0 is allowed);
  - r_A ≤ ½;
  - S < 0.1, strict, through `below_tenth`.

  Size S·hw, "estimate under H-geo".
- **X, not negligible (flag no).** Any one of these:
  - the part verdict differs among the arms;
  - d₁ ≥ 0.1;
  - d₂ ≤ d₁/2 and r_A ≤ ½, with S ≥ 0.1.

  Size: S·hw when both ratio conditions hold, otherwise "≥ d₁·hw (monotone convergence)".
- **U, not certified (flag no).** Every other case, including the structural switches of M7. Size: "d₁·hw, d₂·hw; tail not supported".

Labels and reporting:
- **"endpoint-limited at B = …"** as in M2.
- **Full-n projection (for O4).** A systematic iterative change does not shrink with n, while hw ∝ n^(−1/2). So the size relative to hw grows like √n. The projected size is S·√(n_full/n_pilot): ×1.41 for H2a(i), H2a(ii) and H3c (500 → 1000), and ×1.83 for H2b(i) and H2b(ii) (300 → 1000). A pilot class N transfers to the full run only if the projected S < 0.1.
