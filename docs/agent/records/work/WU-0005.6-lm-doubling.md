### Scope

**In.**
- **.6a The knob.** No production default changes.
  - `__main__.py` gets `--estimator-refine-steps N`, an integer of at least 1. It sets `dataclasses.replace(config, estimator_refine_steps=N)` after `with_seed`.
    - It is refused (exit 64, LPC.PC.7 style, one stderr line, nothing created) together with `--confirmatory`, and for N < 1 or a non-integer.
    - With `--report-only`, the flag must equal `results["config"]["estimator_refine_steps"]`, and a mismatch is refused (64). Absent flag = the preset value.
  - `tools/run_preset.sh` passes the flag through. The lock, tally, meta and refusals are unchanged.
  - The existing `config_record`, provenance `argv` and `iterative_label(config)` already make a variant run self-describing. `report.py` is untouched.
- **.6b The study tool `tools/lm_doubling.py`.** It is not imported by the package. It has two subcommands:
  - `compare <run15> <run30> [<run60>]` (Part B, QoI level).
    - It reads `results.json` per system.
    - For each of the five budget QoIs it reports the point estimate, `lo`, `hi`, n, `n_failed_resamples` and the verdict. The QoIs are H2a(i), H2a(ii) zero/interior, H2b(i), H2b(ii) and H3c. Intervals come from `budget._parts_of`; each point estimate comes from the key stored beside the interval, one named key per part.
    - For every verdict-bearing hypothesis (H1a–H3c, Q-N, robustness) it reports the verdict, plus Δ in natural units where there is a single statistic.
    - It also reports the `handling.cells[*].lm` summaries at each budget: `fraction_above_chi2`, `fraction_late_progress`, median c/ρ², `fraction_no_decrease`, and the non-finite counts.
  - `probe --preset P --seed-id DEV-n --steps 15 30 60` (Part A, per estimate).
    - It runs on the core cell of each system with the test split and the M oracle draws (`study.unit_noise(ctx, "test", "oracle", M, D)`). It uses one trained network, the same library and the same inputs, and `forecast_draws` with the estimator rebuilt as `dataclasses.replace(setup.estimator, refine_steps=k)`.
    - It uses the pipeline's chunking. It writes a JSON summary and an `.npz` of per-estimate ŝ, ν and c, plus PLP errors at H_ref.
    - It refuses a non-DEV id or anything containing "confirmatory". It refuses to start if `pgrep -fa "lpcstudy --preset"` shows a run. It takes `flock -n` on `${LPC_GPU_LOCK:-/tmp/lpcstudy-gpu.lock}` (exit 75 if held, never wait). It sets `JAX_PLATFORMS=cpu`.
- **.6c The runs and the report** (Log), in this order, each after a `pgrep` check:
  1. Smoke, Part B at 15, 30 and 60 (`LPC_THREADS=4`), then smoke Part A.
  2. Pilot Part B at 15 and 30. Both arms use `tools/run_preset.sh pilot DEV-0 runs/dev/wu0005-6/k<N> --estimator-refine-steps N` in the background, with the same `LPC_THREADS=8`, the same host and the same commit.
  3. Pilot Part A at 15, 30 and 60.
  4. Pilot Part B at 60, only under rule D2 below.
  5. The result table, the outcome of the decision rule and the proposed LM-row text, handed to the main session.

**Statistics reported** (per system, QoI and part; hw = (hi₁₅ − lo₁₅)/2 of the design arm):
- r_pt = (q₃₀ − q₁₅)/hw, r_lo and r_hi likewise (signed), d₁ = max(|r_pt|, |r_lo|, |r_hi|), and the verdict at each budget. With a 60 arm: d₂, the same quantity for 30 → 60.
- Part A, per estimate: the fraction with ‖ŝ₁₅ − ŝ₃₀‖_w > 0.1·ρν₃₀ and the same fraction for 30 → 60.
  - The fraction above 0.1·‖ŝ₃₀ − s_true‖_w, for comparison with the WU-0005.4 probes.
  - Quantiles 0.5, 0.9 and 0.99 of ‖Δŝ‖/(ρν), and the median relative change of the per-state PLP MSE at H_ref.
  - c/ρ² > χ²₄(0.999) = 18.47 at 15, 30 and 60, and the transitions above → below (basin or convergence switches).
  - Every fraction carries an SE clustered by state: the SD of the per-state fractions divided by √n_states.

**Decision rule (fixed now; NVVUQ.9, the tenth rule, strict as M9).** It applies per QoI part and system, at pilot.
- **D1, negligible:** d₁ < 0.05, no verdict changes, and the 30-iteration reference is credible. Credible means that Part A at pilot shows median ‖ŝ₃₀ − ŝ₆₀‖ ≤ ½ median ‖ŝ₁₅ − ŝ₃₀‖ over moving estimates, and the 30 → 60 fraction is ≤ ½ the 15 → 30 fraction.
  - Then the error at 15 is ≤ d₁ + 2d₂ ≤ 2d₁ < 0.1·hw (geometric tail with ratio ≤ ½).
  - Size reported: d₁·hw, flag "yes".
- **D2, undetermined:** 0.05 ≤ d₁ < 0.1, or the credibility check fails. Then the pilot is run at 60, with size d₁ + 2d₂, negligible iff that is < 0.1 and d₂ ≤ d₁/2. If d₂ > d₁/2, the result is "not converged at 30": the size is reported as at least d₁ and the flag is "no".
- **D3, not negligible:** d₁ ≥ 0.1, or any verdict changes between 15 and 30. The size reported is d₁·hw (a lower estimate) and the flag is "no". This is a finding for the owner (O5).

All numbers are labelled **DEVELOPMENT (DEV-0)**, conditional on one realization.
