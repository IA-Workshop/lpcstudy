### Scope

**In, step .6a (`lpcstudy/`):**
- **Digest helper.** `provenance.array_digest(a) -> str` returns the SHA-256 hex digest of the float64 values as little-endian bytes in C order (`np.asarray(a, dtype="<f8")`, then `.tobytes(order="C")`). It raises `TypeError` for a non-float64 dtype, so it never converts silently (PRIME.4). On this host the bytes equal `a.tobytes()`, so the digests are comparable with the prefixes in the mathematician's `fixture.py`.
- **Context leaves.** `experiments.context_record(ctx) -> dict` returns `{**ctx.meta, "whiten_digest": …, "unwhiten_digest": …}`, plus `cov_digest` and `state_mean_digest` if the mathematician keeps them (M1). `run_system` uses it in place of `ctx.meta` (`experiments.py:407`). `ctx.meta` is not mutated: it is logged and shared by the cached context. `data.py` is not touched, so no number can change.
  - The covariance is not stored today. If M1 keeps `cov_digest`, `build_context` must keep C or its digest, which touches `data.py`, a core module (see Affected checks).
- **Provenance block** (`provenance.collect`). New keys inserted after `platform`:
  - `cpu: {"model": str, "source": "/proc/cpuinfo" | "platform.processor" | "none"}`. The model is the first `model name` line of `/proc/cpuinfo`, else a non-empty `platform.processor()`, else `"unknown"`.
  - `blas: {"libraries": [{"library", "corename", "config", "error"}], "error"}`. It lists every OpenBLAS mapped into the process (`/proc/self/maps`), opened with `ctypes.CDLL(path, mode=os.RTLD_NOLOAD)` so nothing new is loaded. It tries the symbols `scipy_openblas_get_corename64_`, `scipy_openblas_get_corename`, `openblas_get_corename64_` and `openblas_get_corename` (likewise `*get_config*`). `library` is the path relative to site-packages, e.g. `numpy.libs/libscipy_openblas64_-….so`.
  - `numpy_simd`: the `found` list of `np.show_config(mode="dicts")["SIMD Extensions"]`, or `[]` when the key is absent.
  - `provenance` imports `scipy.linalg` (a pinned dependency), so scipy's OpenBLAS is always mapped when the probe runs.
  - Each probe catches every exception and records it as `"<Type>: <msg>"` (the `git_error` convention). It never raises.
- **Environment.** `ENV_NAMES` gets `OPENBLAS_CORETYPE` and `NPY_DISABLE_CPU_FEATURES` appended (`None` when unset). Each forces a kernel or dispatch choice.
- **Schema string:** per O1.
- **Report.** `report.header_lines` prints one line under the label: `Platform: CPU <model> · BLAS <library> <corename>, …`. For a block without the keys (older runs, `--report-only`) the line is `Platform: not recorded`. The key table is unchanged in form.

### Acceptance criteria (fixed now, VV.3)

Every check is exact (string or bitwise equality). This is metadata: a digest is a deterministic function of the bytes, and a record that changed a number would be a defect. No numerical tolerance applies.

- **A1 `array_digest`** (`test_provenance.py`):
  - **Reference:** `hashlib.sha256(struct.pack("<%dd" % n, *values)).hexdigest()`, with the bytes written separately in the test.
  - **Matrices:** (i) `[[1.0, 2.0], [3.0, 4.0]]`; (ii) a 3×3 with 0.1, 1/3, 1e-300, -2.5 and 5e-324.
  - **Layout and byte order:** a Fortran-ordered copy and a `">f8"` copy give the same digest as the C-ordered `"<f8"` array.
  - **Signed zero:** `[0.0]` and `[-0.0]` give different digests.
  - **Dtypes:** float32 and int64 inputs raise `TypeError`.
  - **Format:** the result is 64 lowercase hex characters.
- **A2 `context_record`** (`test_experiments.py`, fake ctx as a `SimpleNamespace`):
  - The keys are exactly the meta keys plus the digest keys.
  - Each digest equals the A1 struct reference.
  - `ctx.meta` is the same object, with unchanged content.
- **A3 Smoke leaves:**
  - **Runs:** a DEV-0 smoke on CPU with 4 threads through `tools/run_preset.sh` at the branch base, and the same after .6a.
  - **Comparison:** every leaf outside `provenance` and `seconds` is bitwise equal (IEEE bytes, NaN equals NaN), and no leaf is removed.
  - **New leaves:** they are exactly `systems/{lorenz63,rossler,chua}/context/<digest keys>`.
- **A4 Independent digest check:**
  - A separate scratch process rebuilds each system's context with `build_context(system, smoke config, <copy of the run's cache dir>)`, as `fixture.py` does, and computes `hashlib.sha256(ctx.whiten.tobytes()).hexdigest()` (likewise for U).
  - Both digests equal the A3 run's leaves exactly, for the three systems.
- **A5 Provenance key set** (`test_provenance.py`):
  - `KEYS` is the old tuple with `cpu`, `blas` and `numpy_simd` inserted after `platform`, with the types of Scope.
  - `ENV_NAMES` is the old tuple plus the two names, appended. Set values are recorded and unset values give `None` (monkeypatch).
  - `json.dumps(block)` succeeds.
- **A6 CPU probe:**
  - **This host:** `cpu.model` equals the test's own parse of `/proc/cpuinfo` (`^model name\s*:\s*(.*)$`, first match), with source `/proc/cpuinfo`.
  - **Never raise:** with monkeypatched failures (opening the file raises `FileNotFoundError`, `PermissionError` or `UnicodeDecodeError`; file text without `model name`):
    - with `platform.processor()` returning `""`, the record is model `"unknown"`, source `"none"`, and no exception;
    - with it returning `"test-cpu"`, the record is that value with source `"platform.processor"`.
- **A7 BLAS probe:**
  - **In process:** one entry under `numpy.libs` and one under `scipy.libs`, each with a non-empty `corename` and `error` None.
  - **Known truth by forcing:** two subprocesses (`python -I -c`, `OPENBLAS_CORETYPE=Sandybridge`, then `Haswell`) record that corename for both libraries. The test requires `platform.machine() == "x86_64"` (the reference platform, DEC-0022) and fails loudly otherwise.
  - **Never raise:**
    - `ctypes.CDLL` raising `OSError`: each entry has `corename` None and `error` starting with `"OSError"`;
    - a library object without the symbols: the error starts with `"AttributeError"`;
    - opening `/proc/self/maps` raising `OSError`: `libraries == []` and the top-level `error` is set.

    In all three cases `collect()` returns a serializable block.
- **A8 Header** (`test_report.py`):
  - The exact `Platform:` line for a fake block.
  - `Platform: not recorded` for a block without `cpu` and `blas`.
  - The existing per-key table test still holds; it is not edited.
- **A9 Sensitivity** (one more CPU smoke, about 40 s):
  - **The run:** `OPENBLAS_CORETYPE=Sandybridge`, DEV-0, 4 threads.
  - **Record:** `env.OPENBLAS_CORETYPE == "Sandybridge"`, and both corenames are `"Sandybridge"`.
  - **Digests:** `whiten_digest` or `unwhiten_digest` differs from A3's for at least one system. The prediction, from the mathematician's four distinct kernel-family digests, is all three systems. Each system's outcome is reported.
  - The numbers of this run are not compared (DEF-0024 expects them to differ).
- **A10 compare_pilot** (`test_tools_compare_pilot.py`):
  - **Classification:** the fixture new tree plus the digest keys gives no `Unclassified`, and the digest leaves have status `new`.
  - **Branch unchanged:** `select_branch` returns the same result with and without them (the T6 fixtures for B, N and D).
  - **Platform section:** it shows each side's values or "not recorded".
  - **Mismatch:** `platform_mismatch` emits the line when the corenames differ and nothing when they are equal. Two fixtures that differ only in `provenance.cpu`/`blas` give identical leaf statuses, branch and exit code.

### Applied-mathematician must confirm before execution

- **M1, what the digest covers.** W and U only, or also C (`np.cov` uses a BLAS product, so C is itself kernel-dependent) and `state_mean` (a numpy reduction, SIMD-dispatched)? These would localize the divergence: C differs means upstream of `eigh`; C equal with W/U different means `eigh` or the products. The planner recommends W, U, C and `state_mean`, with C's digest returned from `build_context` without changing C.
- **M2, byte order and layout.** Little-endian `<f8`, C order, no shape or dtype prefix: m = 3 is fixed and float64 is enforced. Or a prefix?
- **M3, the raw `eigh` output.** The planner recommends not digesting it. The eigenvector signs and order are implementation conventions, and digesting them would change `_symmetric_root`'s return (in `data.py`). M1 already localizes.

XLA's ISA choice is unrecorded beyond the model and `XLA_FLAGS`. Should a digest of the `/proc/cpuinfo` `flags` line be added (for VMs that mask features)?
