**M2: byte layout. Decision: raw bytes, no shape or dtype prefix, explicit little-endian `<f8`, logical row-major (`np.asarray(a, dtype="<f8").tobytes(order="C")`).**
- **No prefix.** The digest is a same-key equality fingerprint. The shape is fixed by the key ((m,) or (m, m), with m = 3), and the dtype is enforced by the `TypeError`. Two arrays with equal bytes and different shapes can arise only from a code change that leaves the byte count unchanged, which cannot happen for these four keys. A prefix would also break comparability with the independent reference `sha256(ctx.whiten.tobytes())` (A4) and with the WU-0002.12 `fixture.py` prefixes.
- **State the format in the docstring:** "SHA-256 of the IEEE-754 binary64 values, little-endian, row-major (C order)".
- **Explicit `<`.** It makes the digest host-independent: on a big-endian host, native `tobytes()` would differ.
- **The order is load-bearing.** W and U are **not bitwise symmetric** (`array_equal(W, W.T)` is False for all three systems under Haswell; computed products are not exactly symmetric). A Fortran-order read of the memory, or a transposed view, would therefore give a different digest. A1's Fortran-copy check tests exactly this property.
- **Dtype check.** Accept only `dtype.kind == "f"` and `itemsize == 8`. This accepts `>f8`, as A1 requires, and rejects float16, float32, longdouble (`f16`), int, complex and object.
- **Bitwise identity by design.** Signed zeros and NaN payloads give different digests. A1 tests the ±0 case.

**"As built".**
- The four arrays are the objects stored on `SystemContext`, digested in `run_system` from the cached context.
- **Verified with `ctxcheck.py`.** All are numpy-owned, C-contiguous, native (`=`, little-endian) float64 `ndarray`s, and nothing in `lpcstudy/` mutates them in place (grep).
- **None of the four is converted from jax.**
  - The only jax-to-numpy step is upstream: `simulate_trajectory` returns `np.asarray(states)`. That is a zero-copy, read-only, bit-preserving view of the XLA buffer, float64 because `systems.py:23` enables x64.
  - `state_mean`, C, W and U are then computed by numpy and LAPACK from that view.
  - The consumers' `jnp.asarray(ctx.unwhiten)` copies (`dynamics.py:83`, `estimation.py:73-74`) are bit-identical under x64. They are not what is digested, and they need not be.
- **On this host,** `np.asarray(a, "<f8")` makes no copy, so A4's `sha256(ctx.whiten.tobytes())` is a valid independent reference.

**M3: raw `eigh` output. Decision: do not digest (agree with the planner).**
- **(a)** Given C, `eigh` is kernel-invariant here: 4 families × 3 systems, bitwise. So it adds no localization for any observed class.
- **(b)** The eigenvector signs and column order are LAPACK conventions. W and U are invariant to them, but an `eigh` digest is not. It would create a false-difference channel: under DEC-0019's literal "context differs", it would select branch D (F1).
- **(c)** It would change `_symmetric_root`'s return.
