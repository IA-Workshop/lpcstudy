## Findings

**R1 (low). `capture` docstrings say "copies"; the function stores references.**
- **Where:** `lpcstudy/analysis.py:338-343` and `:584-589`.
- **What:** the docstrings say "filled with copies of what the function already computed". In fact, `capture["local_dim"]` is the cell's own `oracles["test"].local_dim` (analysis.py:366, 376), and `n_lib`, `inverse_dim`, `seed_sq` and `thresholds` are the arrays the function goes on to use. The copy happens later, in `StateDump.record_extra` → `clean` (dump.py:161, 211); `test_dump` checks it with `not np.shares_memory`.
- **Why it matters:** neutrality holds today. Nothing writes to these arrays between the capture and `record_extra`, and `clean` copies. But the Log's neutrality argument ("the captured arrays are copies") is stated at the wrong layer. Any other consumer of `capture` would alias study arrays.
- **Fix:** either reword both docstrings ("references to the arrays the function uses; the caller must copy them, as `StateDump.record_extra` does"), or copy inside the guarded branch. Copying changes no result.

  - **Answer (developer, fix round 1):** reworded in a687785: both `capture` docstrings now say references to the arrays the function uses, copied by the caller (`StateDump.record_extra` does); the flag-off path is untouched.

**R2 (low). `record_extra` and `collect` do not enforce the `/2` invariant "every `/1` key keeps its name and meaning".**
- **Where:** `lpcstudy/dump.py:209-211` and `:363-364`.
- **What:** `record_extra` accepts any full key, and `collect` writes those keys with `put(name, value)` after every `/1` key. An extra key equal to a `/1` key would silently replace that array (PRIME.4).
- **Why it matters:** nothing can trigger this today, because the only caller (experiments.py:656) passes `h1a/` and `h1c/` keys. But the schema guarantee rests on the caller alone.
- **Docstring gaps in the same code:** `collect`'s `Raises` (dump.py:258-261) does not list the missing extra record (the `KeyError` from `self._extra.pop(system)`). The class docstring (dump.py:173-175, "feeds it from four places") does not list `record_extra`.
- **Fix:**
  - refuse, with a `ValueError`, any key not under `h1a/` or `h1c/` in `record_extra`;
  - and/or raise in `collect` if `name in out` before `put`;
  - update the two docstrings.

  - **Answer (developer, fix round 1):** fixed in a687785: `record_extra` raises `ValueError` for a key outside `h1a/` and `h1c/` (`EXTRA_GROUPS`) and for a key already recorded, recording nothing when it refuses; the class docstring names `record_extra` and `collect`'s `Raises` lists the missing extras and the `TypeError`; `test_record_extra_refuses_keys_outside_h1a_h1c_and_a_key_recorded_twice` covers both refusals.
