## New findings

**R17 (low-medium; PRIME.4, acceptance e4). C4 silently skips a required kind whose `n_estimates` is 0 or absent.**
- **Where:** `section_c4`, `tools/rehearsal_diagnostics.py` 1873–1875 (`n = lm.get("n_estimates")`; `if not n: continue`).
- **The defect:**
  - Production always writes `n_estimates`, with 0 for a kind without estimates (`pipeline.py` 653–658).
  - That is right to skip for the eval kind of a sweep cell. But the same line skips the core cell's oracle or eval kind, and a summary without the key.
- **Probe** (`lm_cells`/`CFG` of the tests): core oracle with `n_estimates = 0`, core eval with 0, and core oracle with the key deleted. Each gives exit 0, no "not computable" line, no reading for that kind, and the section ends with "0 finding(s) in the bands and the relation".
- **Why it matters:** e4 requires a missing input to be "not computable" (exit 2). Here a required reading vanishes, and the section reads clean.
- **Fix:**
  - Define the required kinds: the oracle kind in every target cell, and the eval kind in the core cell.
  - For those, an absent or zero `n_estimates` is `rep.nc`.
  - Skip only the eval kind of sweep cells, and say so in one line.
  - Add the three probe cases as a test.
  - **Answer (developer, fix round 3):** fixed in this round's commit: `section_c4` requires the oracle kind of every target cell and the eval kind of the core cell (absent or zero `n_estimates` is "not computable"); the sweep cells' eval kind is skipped in one stated line; `test_r17_...` runs the three probes.

**R18 (low; PRIME.4, acceptance e3). The N_lib check compares whatever cells happen to carry `lm`; a missing library-sweep cell or summary shrinks the group silently.**
- **Where:** `nlib_exact_check` 1821–1828 (`if m and ... "lm" in cell`, and the singleton `continue`), and `section_c4` 1888–1889 (`nc` only if no group at all was checked).
- **Probe:**

  - With one fewer, the group would be a singleton, skipped with no line.
  - The printed size list shows the gap only to a reader who knows the expected sizes.
- **Why it matters:** the check is the exact defect test of M6. A cell that is absent is never compared, and nothing counts that.
- **Fix:**
  - Derive the expected groups from the config: `library_sweep_noises` × `library_sizes`, plus the noise-sweep cell at the core library where one exists.
  - Print `rep.nc` for each expected cell or `lm` that is absent.
  - Keep the singleton skip only for ρ values that by design have one size.
  - Add a test with one missing cell and one missing `lm`.
  - **Answer (developer, fix round 3):** fixed: `nlib_expected_cells` derives the expected cells from `library_sweep_noises` x `library_sizes` (core cell excepted); each absent cell or `lm` is "not computable", also when a group shrinks to one; a by-design single size is stated; `test_r18_...`.

**R20 (low; acceptance e2/e4 domain). `chi2_relation` guards `π < 1`, but the quantile exists only for π < 0.5.**
- **Where:** 1786–1788.
- **Probe:**
  - With f = 0.501, π = 0.5, so the probability is 1, Q = inf and SE, z = NaN.
  - With f in (0.501, 1.001), the probability is above 1, so Q = NaN.
  - Each prints "z nan ... FINDING (outside 4 SE)".
  - The test's NotComputable probe (f = 1.5) exercises only the wrong boundary.

- **Fix:**
  - Guard `π < 0.5`, that is, `0.5/(1 − π) < 1`, and print "not computable" with the reason.
  - Test at f = 0.501 and 0.6.
  - **Answer (developer, fix round 3):** fixed: `chi2_relation` requires a share below 1/2 and says "not computable" otherwise; the cell-level line is not a FINDING and has no NaN; `test_r20_...` (f = 0.501, 0.6, 1.5).
