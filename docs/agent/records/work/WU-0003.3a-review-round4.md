**R14 (low; developer; PRIME.4 and the G2 exit rule). A `core_systems` leaf that is empty or not a list is not checked.**
- **Where.** tools/rehearsal_report.py:1272-1284.
- **Probe.**

  | `core_systems` | Result |
  | --- | --- |
  | `[]`, with `chua` deleted | **exit 0**, 0 items, "governs 8 of 8 parts" |
  | `"lorenz63"` | Iterated as characters: 8 items "system l: not in results.json …" and three nonsensical notes. Exit 2. |
  | `3` | `TypeError` outside `attempt`: "INTERNAL ERROR: run", a partial report, exit 2 |

- **Why it matters.**
  - The `[]` case is the one remaining exit-0 path with a missing core system. `if core and …` (line 1282) and the empty loop act as a silent default of "nothing required".
  - Round 3 asked for an unreadable leaf to be "not computable", with no default.
  - It needs a malformed configuration (production writes the preset's tuple), hence low.
- **Fix.**
  - Accept only a non-empty list or tuple of strings.
  - Otherwise record `rep.nc("config core_systems", f"{raw!r} is not a non-empty list of system names; …")` and set `core = []`.
  - Add a unit test: `[]` with `chua` deleted must exit 2.

**Answer R14 (developer): fixed in the fix-round-6 commit.** Only a non-empty list or tuple of non-empty strings is accepted; `[]`, a string, an int, `None` and `['']` are each one counted "config core_systems" item (exit 2), nothing is read letter by letter and nothing crashes. Test: `test_malformed_core_systems_is_one_counted_item`.

**R15 (low; developer; robustness regression, "the report is still printed in full"). An unexpected exception in `verify_dump` aborts the whole report.**
- **Where.** `verify_dump` (lines 857-872) catches only `NotComputable`. It is called directly in `run` (line 1303), not through `attempt`.
- **Probe.**
  - **Out-of-range `core/ref_index`.** With the Rössler `core/ref_index` set to 9, `kappa_inputs` raises `IndexError` at line 835. `main` gives "INTERNAL ERROR: run … the report above is partial", exit 2. Chua and the summary are never reported.
  - **1-D `state_mse/A5`.** The same happens.
  - **Before this round.** The same inputs were met inside `kappa_from_dump` under `attempt`. They gave per-row INTERNAL ERRORs and a complete report.
- **Why it matters.** The exit stays 2, so nothing looks passing. But the record loses the remaining systems, and the module docstring promises that the report is printed in full.
- **Fix.**
  - In `verify_dump`, also catch `Exception`, but not `Refused`, for each spec. Record it with `view.rep.internal(...)`, then call `view.fail(...)`.
  - Optionally add a test with `ref_index` out of range: exit 2, all three systems reported, Rössler information 0.

**Answer R15 (developer): fixed in the fix-round-6 commit.** `verify_dump` also catches any other exception per spec (not `Refused`), records it with `rep.internal` as a counted item and marks the dump failed; the other systems, H3a and the summary are printed. Tests: `test_an_unexpected_dump_exception_is_counted_and_the_report_is_complete` (`ref_index` 9 and a 1-D `state_mse`: exit 2, information 8 of 12) and `test_mismatch_elsewhere_still_wins_over_an_internal_error` (exit 1).

**R16 (low; developer; text). Two docstrings still describe per-leaf use.**
- **Where.**
  - The module docstring at lines 107-108: "A dump that does not reproduce its results leaf is never used: that row falls back to the range".

**Answer R16 (developer): fixed in the fix-round-6 commit.** Both docstrings now say that a dump with any defect (provenance, input or reproduction) supplies nothing to any row of its system.
