## Plan (written before execution)

- **Scope:** in: `tools/run_tests.sh` and `tools/run_preset.sh` export `PJRT_NPROC` and `NPROC`, both equal to `LPC_THREADS` (default 4, the wrappers' existing validation 1..99), to the child process; tests for it; a recorded verification that the cap works. Out: any `XLA_FLAGS` entry (an unknown XLA flag aborts the process; `intra_op_parallelism_threads=N` from the 2019 jax issue is not a registered flag: do not use it); `lpcstudy/` code; DEF-0012 (`cKDTree` `workers=-1`, a separate small unit). Source: `docs/agent/notes/2026-10-11-research-xla-threads.md` and DEC-0010: `PJRT_NPROC` then `NPROC` are plain environment variables read by getenv in XLA's `DefaultThreadPoolSize()` (cannot abort XLA); documented only in a source comment, XLA at the commit pinned by the jax-v0.11.2 tag (that it equals the XLA inside the jaxlib 0.11.2 wheel is UNCONFIRMED, so the verification below is required). Variables must be set before `import jax`.
- **Definition of done and acceptance criteria (fixed now, VV.3):**
  1. Both wrappers export `PJRT_NPROC` and `NPROC` equal to the validated `LPC_THREADS` value to the child (unit tests with the existing fake-runner machinery: the child's environment has exactly these values, for the default and for `LPC_THREADS=2`; the wrappers still refuse an invalid `LPC_THREADS`; neither wrapper sets or alters `XLA_FLAGS`, and an `XLA_FLAGS` supplied by the caller is passed through unchanged or refused exactly as before: read the current behaviour and keep it; a test pins that `XLA_FLAGS` does not appear in what the wrappers add).
  2. A recorded verification on this machine that the variables take effect with the pinned jax/jaxlib 0.11.2: a short float64 jitted CPU workload (for example repeated 2000x2000 matmuls with `jax.block_until_ready`) run with `PJRT_NPROC=NPROC=1`, `=2` and unset; for each, process CPU time divided by wall time (from `resource`/`time.process_time`) and the thread count named XLA* in `/proc/self/task/*/comm`; the claim to verify is that the CPU/wall ratio is about the cap (at most cap + 0.5) while unset uses more than 3 on this 4-core machine. If the variables do NOT cap the pool, record that, change nothing in the wrappers, and refer (`/refer`): do not keep an ineffective setting.
  3. No change to any `lpcstudy/` file; no new dependency; the existing wrapper tests pass unchanged.
- **Affected checks:** `tests/unit/test_tools_run_tests.py`, `test_tools_run_preset.py` (unit tier); `tests/integration/test_preset_wrapper.py` once at the end (it runs the smoke preset through the wrapper and compares with a direct run: the env change must not alter `results.json`; the comparison already excludes `seconds` and `provenance`).
- **Owner checkpoint:** wrapper code (with WU-0012): needs owner review before freeze.
