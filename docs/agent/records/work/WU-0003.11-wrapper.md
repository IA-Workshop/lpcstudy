## Plan (written before execution)

Branch `wu/0003-11-wrapper`, created from the tip of develop e3b2645.

- **Why.** The rehearsal runs R1 (pilot, DEV-1, GPU, dump on) and R5 (full, DEV-2, GPU, dump on) in WU-0003 (A4 table; amendments .7b, .7c) are launched through `tools/run_preset.sh` (A4: "Every run is launched through `tools/run_preset.sh`"). The wrapper accepts only `--device`, `--systems`, `--skip-robustness` and `--estimator-refine-steps`, so the CLI flag `--states-dump` (WU-0003.7b) cannot be passed.
- **Scope in.**
  - `--states-dump` accepted once by the wrapper as a bare flag and passed to the CLI unchanged, in the given place among the pass-through arguments.
  - Refused (exit 64, one stderr line, nothing started, before the lock and the tally) if given twice, or with an argument (a following word that does not start with `--`, or the form `--states-dump=X`).
  - Recorded in `run.meta.json`'s `command` like the other flags (it is part of the command array).
  - The header comment of the wrapper documents it.
- **Scope out.** No other behaviour change. The wrapper never accepts the sealed-run flag (the check on any argument containing that word is first and unchanged); the CLI refuses `--states-dump` with the sealed flag and with `--report-only` (`choose_states_dump`), and the wrapper never passes `--report-only`. No change to `lpcstudy/`. No run of any preset.
- **Definition of done.**
  - The behaviour above, with the tests below passing in the one run of the radius.
  - The diff touches `tools/run_preset.sh`, `tests/unit/test_tools_run_preset.py` and this file only; no existing test is edited.
- **Acceptance criteria** (fixed now; tolerance none, all are exact comparisons of argv lists, exit codes, counts and strings; reference: the plan text above and the CLI's `store_true` contract, independent of the wrapper):
  - a1: `smoke DEV-2 ... --states-dump --estimator-refine-steps 30 --systems lorenz63 --skip-robustness` gives a CLI argv tail `--systems lorenz63 --states-dump --estimator-refine-steps 30 --skip-robustness` with the flag once, and the meta `command` ends with the same tail.
  - a2: the flag is bare as the last argument and before `--device`.
  - a3: without the flag, no mention in the argv or the meta `command`.
  - a4: with and without the flag the two runs differ by the flag alone (argv with the out-dir masked, the environment variables the wrapper sets, the timeout call).
  - a5: refused with exit 64, one line naming the flag, with the lock held (so the check comes before the lock), no fake called, no meta and no `runs/` created, for: twice (adjacent and apart), a digit, word, boolean, empty or dash-led argument, a system name after it, and the `=` forms.
  - a6: with the sealed flag it is still refused (64, one line, nothing started).
  - a7: a CPU pilot carries the flag to the background child after the lock and the tally (`check --hours 0`).
- **Affected checks.** By §4.2, `tools/<t>.sh` gives `tests/unit/test_tools_run_preset.py` (see the Log for the tool's output and the hand derivation).
