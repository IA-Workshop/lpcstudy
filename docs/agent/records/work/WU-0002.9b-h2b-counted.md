## Plan (written before execution, by the main session)

- **Scope:** `lpcstudy/analysis.py` `h2b_knob_response` and its tests. Part (i), the verdict-bearing one, bootstraps through `_boot` (integer salt 3, `PRIMARY_LEVEL`) and drops failed resamples; WU-0002.11b counts them as `n_dropped_resamples`. Change: use `block_bootstrap_counted` (`lpcstudy/statistics.py`) at the same integer seed (`config.seed + 3`, as `_boot` does: read the code), the same level and the same block length; take the verdict from `criterion_verdict` with the failed-resample count in the A3 tail (as the H2c and H2d lanes do); report `n_failed_resamples`. Keep `n_dropped_resamples` too if it is already a published key, as an alias with the same value; do not remove existing keys silently: list the key changes. Out: every other file in `lpcstudy/`; `defects.md` (the main session appends the DEF-0019 status line; the proposed line is in the Log).
- **Acceptance criteria (fixed now, VV.3):**
  1. A unit test that, with all-finite resamples, the new interval is BITWISE equal to the old `_boot` interval on a fixed synthetic input (independent reference: a verbatim copy of the old `_boot` body inside the test; justification: when nothing fails the percentile computation is the same).
  2. A unit test with an injected non-finite resample (monkeypatch the statistic or the resample values) showing that the failed resample goes to the A3 tail and `n_failed_resamples` equals the injected count, and that the verdict becomes `inconclusive` when the count reaches the tail threshold `floor((B - 1) a) + 1` with `a = (1 - level)/2` (DEC-0012). Mirror how the H1b-PLP and H2c code and `statistics.criterion_verdict` do it.
  3. Smoke: a leaf-by-leaf IEEE-byte comparison of the DEV-0 smoke `results.json` at the develop tip against the final code, excluding `provenance` and `seconds`: no changed numeric leaf. Allowed differences: the new `n_failed_resamples` leaf (value 0 at smoke) only.
  4. The DEF-0019 status line is NOT edited into `defects.md` in this branch; the proposed line is in the Log.
- **Affected checks:** `python3 tools/test_impact.py --base develop --explain`, plus `tests/unit/test_data.py`, `tests/unit/test_validation.py` and `tests/unit/test_tools_test_impact.py` by hand (DEF-0016); the §4.9 checklist (one line per item) is logged before every test invocation; each set once via `tools/run_tests.sh`; on a failure fix, `--lf`, then the radius once; no test is loosened; development seeds only, never `--confirmatory`.
