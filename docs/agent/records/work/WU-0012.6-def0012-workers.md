## Plan (written before execution, by the main session)

- **Scope:** in: `lpcstudy/ensemble.py` (the `cKDTree.query(..., workers=-1)` call of `AnalogLibrary.query`, about line 189) and `lpcstudy/oracle.py` (`local_dimension_counted`, about line 79) pass the `LPC_THREADS` value (default 4) as `workers`. One helper reads the variable (in `ensemble.py`, which `oracle.py` already imports, so there is no new module and no new import edge; the graph fixture is untouched, and the imports are read by hand to confirm it). The accepted values are those of `tools/run_tests.sh`: an integer from 1 to 99 (unset or empty means 4, as the shell `${LPC_THREADS:-4}` does). Any other value raises `ValueError` naming `LPC_THREADS` (no silent fallback, PRIME.4). Out: every other file in `lpcstudy/`; `defects.md` (the main session appends the DEF-0012 status line on develop; the proposed line is in the Log).
- **Acceptance criteria (fixed now, VV.3):** (1) a unit test that wraps `cKDTree.query` and asserts `workers ==` the `LPC_THREADS` value at both call sites, for `LPC_THREADS` unset (4), `2` and `8`, and that both call sites raise for `0`, `-1` and `abc`; (2) a unit test that the query results are bitwise identical for `workers=1` and `workers=4` on a fixed synthetic library (reference: the same query with `workers=1`; justification: a k-d tree query does not depend on the worker count); (3) a leaf-by-leaf IEEE-byte comparison of the DEV-0 smoke `results.json` at the develop tip against the final code, excluding `provenance` and `seconds`: zero changed, added or removed leaves; (4) the proposed DEF-0012 status line is in the Log.
