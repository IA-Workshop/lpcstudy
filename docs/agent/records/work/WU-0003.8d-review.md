## Findings

### R1 (medium; correctness of the label). Widening about the point is not a widening when the point lies outside its interval, so a verdict can improve and be labelled BLOCK-SENSITIVE.
- **Where.**
  - `tools/rehearsal_diagnostics.py:1767-1769` (`widen_interval`).
  - `:1800`: the usability guard checks `lower > upper` and NaN, but not `lower <= point <= upper`.
  - `:1807-1811`: the widened verdict is compared with `!=` in either direction.
- **Evidence.** This is an offline call of the branch's `widen_interval` and `criterion_verdict`, not a test run. H1a (closed band [0.75, 1.25]) with point 0.70 and recorded interval [0.749, 1.10] is inconclusive. With f = 1.05 the "widened" interval is [0.75145, 1.12], which **passes**, and the row would read BLOCK-SENSITIVE. A percentile interval can exclude θ̂ when the bootstrap distribution is skewed or biased. The candidates are the median statistics (H2a(i) median range, H1a ratio of median fits) and the A3 tail placement.
  - On R1 and R5 all 48 points lie inside their intervals (relative position 0.29 to 0.60), so the recorded outputs are unaffected.
- **Why it matters.** More variance can only move a verdict toward inconclusive. A label raised in the favourable direction is a wrong report-only statement, and nothing detects it. The tests cover neither this case nor the infinite-bound case (A3), which is handled correctly today but not guarded by a test.
- **Required fix.**
  - In `block_sensitivity`, raise `NotComputable` (counted and printed like the other classes) when `not lower <= point <= upper`. The reason should say that the widening about the point is undefined there.
  - Alternatively, if the applied-mathematician prefers, widen about the interval midpoint, but record that choice against note §2.5.
  - Also assert the invariant "widened verdict ∈ {baseline, inconclusive}". Breaking it would be an internal error, not a label.
  - Add hand-worked tests:
    1. the point-outside case above gives not computable;
    2. an infinite upper bound (H3c, `[0.9, inf]`) stays `[0.9 - f(0.1), inf]`, inconclusive, not sensitive.
