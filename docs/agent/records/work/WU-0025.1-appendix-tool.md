## Plan (written before execution)

- **Scope.**
  - **In:**
    - `render` accepts `--development` several times (the ensemble DEV-1, DEV-3, DEV-4) and a new repeatable `--extension` (development runs of systems outside v3). They fill the existing placeholder `{{dev_appendix}}` of the section `## A. Development context [DEVELOPMENT]`. The template and `design_constants.json` do not change.
    - New sources `dev:<seed id>` and `ext:<system names joined by +>`, valid only inside the `[DEVELOPMENT]` section; each is hashed in `sources.json` and re-hashed by `check`.
    - Appendix A.1 (ensemble by seed) and A.2 (extension, per system), both from stored leaves only.
    - Independent checks in `check` for the labels, for "no overall verdict", for PROVISIONAL and for the banned wording in the appendix.
    - The first rendering in `docs/agent/notes/2026-10-23-appendix-a-development.*` (document, trace, sources, figures), then `check` on it.
  - **Out:**
    - any change to the sealed sections, the template, the constants, the figures, `promote`, `lpcstudy/`, the ledger, the sealing script and any flag naming the sealed run;
    - any aggregate across seeds or runs (no mean, spread, range, count of passes, pooled or overall verdict, O7), any recomputation of a verdict or gate;
    - a rerun of any development run;
    - a standalone appendix command (the first rendering is a `render` over the DEV-2 pair as host, see Note 1).
- **Behaviour.**
  - **Mode.** Legacy mode (exactly the present behaviour, source name `dev`) when there is at most one `--development` and no `--extension`. Appendix mode otherwise (sources `dev:<seed id>` and `ext:<systems>`).
  - **Order.** `dev:` sources by seed id, `ext:` sources by name; the order on the command line has no effect. Tables are system-major for the ensemble (seeds side by side in adjacent rows) and run-major for the extension.
  - **Contents** (every value is a traced leaf or a builder string saved in `meta`):
    - run table (both parts): label, seed id, systems, preset, commit, backend, `complete`, `dirty`, wall seconds, start and end, SHA-256 of the file;
    - gate flags V1, V2, V4, V5, V6, V7 and `gate_pass` per run and system, with the mark PROVISIONAL in the system cell when the stored `gate_pass` is not true, and a remark that lists, from the stored flags, the failed checks per such system;
    - reported values per run and system: `lambda_max`, CP median VPT (V3, reported, no bar), V7 median slope;
    - stored per-system verdict words, three tables: primary (H2a, H2b, H3c), secondary (H1a to H1d, H2c to H2e, H3a, H3b), and Q-N (both readings) with the reported gain bound word;
    - A.1 only: the 18 primary-part estimates with interval, level and stored verdict per seed and system.
  - **Labels.** Each table is headed by a line that starts with `Development context: not a hypothesis test.`, names the seed ids and says `development seeds, exploratory, not confirmatory`. A.2 tables also say `systems outside the v3 design; exploratory readings pre-specified in WU-0021.2` and `per-system only, no overall verdict`.
  - **Refusals** (exit 2, nothing written): a file that `classify` does not call a development run; an incomplete run (`provenance.complete` not true: PRIME.4, WU-0026 F2); a duplicate (same realpath or same SHA-256, also against the official and cross-check files); two `--development` runs with the same seed id; a `--development` run whose `core_systems` are not the three v3 systems; an `--extension` run with an empty `core_systems` or with a v3 system; two `--extension` runs sharing a system.

  - D-2. The extension verdict words are shown per system, but the stored overall word (`per-system only`) is never quoted; `check` fails any `dev:`/`ext:` row at `verdicts/<id>/verdict`.
  - D-3. The row-level PROVISIONAL rule is derived from the stored flags, so every system whose stored `gate_pass` is not true is marked, not only the two named in the task (lorenz96_4 is also stored false; the figures come from the files).
