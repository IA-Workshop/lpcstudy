## Findings

**R1 (medium): the report claims endpoint noise never pushes a part toward N, and one row contradicts this.**
- Where: report §3, line 65: "no floor was applied, so noise pushes toward X or U, never toward N".
- The contradicting row is Rössler H2b(ii):
  - With all three components it is class N, because d1 = 7.58e-5 comes from `lo`.
  - On the point alone, r1_pt = -2.83e-5 and r2_pt = 2.63e-5. Since 2.63e-5 > d1_pt/2 = 1.42e-5, the point-only class is U.
- So the endpoint change raised d1 enough to satisfy d2 <= d1/2, and that pushed the part toward N.
- Mathematics check M2 claims only "never ... through S". The report's paraphrase drops that qualifier, and the ratio condition is a second path.
- The substantive reading is unaffected, since S = 1.3e-4. But the general statement is false, and the owner may rely on it for the endpoint-limited rows.
- **Fix:**
  - Issue an erratum or a new report version with a manifest line, because the hash of the current report is recorded. It should say that endpoint noise can satisfy the ratio condition, and that the N of Rössler H2b(ii) rests on the `lo` change.
  - Route the asymmetry to `applied-mathematician` as a note on M2 and rule R. This is not a change to the rule.

**R2 (medium): DEF-0027 gives the wrong reason for the U parts and defines r_A incorrectly.**
- Where: `docs/agent/records/defects.md`, DEF-0027 description.
- It says "6 are U (undetermined, 3 of them only because r_A, the fraction of estimates above the chi-square threshold, exceeds one half)".
- The reasons stored in `pilot-compare.json` show otherwise:
  - only **1** U part is due to r_A: Rössler H2b(i), r_A = 0.571;
  - the other 5 fail d2 <= d1/2: chua H2a(ii) interior and zero, lorenz63 H2a(ii) interior, rossler H2a(i) and rossler H3c.
- r_A is not a chi-square fraction. It is max(F(60→120)/F(30→60), T(60→120)/T(30→60)), computed on per-estimate moves greater than 0.1 ρν30.
- **Fix:** append a dated correction line to DEF-0027. The defect log is append-only.

**R3 (medium): DEF-0027 states the X results more strongly than rule R supports.**
- Where: the DEF-0027 title and description: "leaves an iterative error above 10% ... in most Lorenz-63 and Chua primary quantities".
- Under rule R, X is "not negligible", and its sizes rest on assumptions:
  - when d1 >= 0.1, the error at 15 exceeds 0.1 hw only under monotone convergence (M1);
  - when S >= 0.1, the size is an estimate under H-geo.
- 3 of the 7 X parts are endpoint-limited at B = 500. DEF-0027 does not say so, though the report does (§3, line 65):
  - chua H2a(i) and lorenz63 H2b(ii) are N on the point alone;
  - lorenz63 H2a(i) is U on the point alone.
- Chua has 3 of 6 parts in X, which is not "most". 7 of 12 holds only when the two systems are pooled.
- **Fix:** append a correction. It should state:
  - "class X (not negligible under rule R) in 4 of 6 Lorenz-63 and 3 of 6 Chua parts";
  - the conditions;
  - the three endpoint-limited X parts.

**R4 (low to medium): the report and DEF-0027 describe O5 option 2 differently.**

- The report says the change "could be folded into the seed-step regeneration so that no extra reference run is needed". It gives no cost.
- DEF-0027 says it "costs run time and changes every PLP number, so it needs a new reference run".

- **Fix:** align the two texts in a DEF-0027 append and in a report erratum or new version.

**R5 (low): the report says S is the lower estimate when a ratio condition fails, but rule R says d1·hw is.**

- **Fix:** correct the sentence in the erratum or new version.

**R6 (low): the size given for U parts omits d2·hw.**
- Where: the "size in QoI units" column of the report table for the U rows.
- Rule R prescribes "d1·hw, d2·hw; tail not supported" for U. The report gives d1·hw only.
- Where d2 >= d1, the column understates the observed movement:
  - chua H2a(ii) interior: d2 = 2.1·d1, so d2·hw = 0.0057 against the printed 0.0027;
  - rossler H3c: d2 > d1;
  - rossler H2a(i): d2 = d1.
- **Fix:** add d2·hw for the U rows.

**R7 (low): the size label and the class definitions do not account for the chua H3c structural switch.**
- Where: the report table row for chua H3c, and §2 lines 29 to 31.
- The size is labelled "S hw (estimate under H-geo)". But K switches discretely from 8 to 5 at 15 → 30, and line 64 says the switch blocks the S-based X bullet. An H-geo estimate is not meaningful across a discrete switch.
- The tool sets `supported` without regard to `structural` (`tools/lm_doubling.py` lines 348 and 359). That matches the letter of rule R ("S·hw when both ratio conditions hold"). It does not match M7, which says structural switches "make the part class U".
- §2's definitions of N and of the third X bullet omit the "no structural switch" condition that the tool applies.
- The flag is "no" under either reading.
- **Fix:**
  - state in §2 the precedence the report uses: X before U, and a structural switch blocks N;
  - label the chua H3c size ">= d1·hw" or add the caveat;
  - leave the precedence question to `applied-mathematician`.
